# Notes: issues #1098, #1099, #1100 — not applicable to current repo state

These three issues describe refactors of infrastructure that doesn't exist in this
repository. Recorded here instead of being silently closed or force-implemented
against a made-up structure.

## #1100 — Centralize Zustand/Redux store slices under `apps/interface/store`

Assumes an existing Zustand/Redux store with multiple slices to reorganize.

Actual state: neither `zustand` nor `redux`/`@reduxjs/toolkit` is a dependency
anywhere in the repo, and there is no `apps/interface/store` directory. Client
state is handled with plain React Context (`apps/interface/src/context/WalletContext.tsx`,
`apps/interface/src/context/ThemeContext.tsx`).

There is nothing to centralize or extract selectors from. Doing this issue as
written would mean introducing a state library and a store from scratch — a new
feature/architecture decision, not the refactor the issue describes. Needs a
decision from the team on whether such a store is actually wanted before any
work here makes sense.

## #1099 — Remove dead code and unused exports from `apps/components-lib`

Assumes a `components-lib` package under `apps/`.

Actual state: the `apps/` workspace only contains `apps/interface` (see root
`package.json` → `"workspaces": ["apps/*"]`). There is no `components-lib`
package, so there's no `src` tree to run `ts-prune`/`knip` against for this
issue.

If a dead-code sweep is wanted, it would need to target `apps/interface/src`
instead (components live under `apps/interface/src/components`), which is a
different, smaller scope than the issue describes.

## #1098 — Standardize form components on `FormField` wrapper

Assumes `Input.tsx`, `Select.tsx`, `Textarea.tsx`, and a `FormField` wrapper
inside `apps/components-lib/src`.

Actual state: none of these files exist anywhere in the repo (confirmed via
repo-wide search), and there is no `components-lib` package for them to live
in. `apps/interface/src/components/ui` has no generic form input components at
all currently.

Same blocker as #1099/#1100: the target package doesn't exist, so this issue
can't be actioned without first deciding to build the missing components,
which is out of scope for what the issue asks (standardizing *existing*
components).

## Recommendation

Before re-filing or re-scoping these, confirm against the current repo
(`apps/interface` only, Context-based state, no shared component library)
rather than whatever project generated these issues.
